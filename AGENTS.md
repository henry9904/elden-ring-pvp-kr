# Agent Guidelines

This document is for AI coding agents (Antigravity, Claude Code, Copilot, etc.).
Read this **before** making any changes to this repository.

---

## CI Checks That Must Pass

The CI pipeline runs four jobs. Every job must pass before merging to `main`.

### 1. Markdown Lint (`markdownlint-cli2`)

- Config: `.markdownlint.json`
- **Do not** write inline object literals inside `replace()` callbacks — markdownlint flags `({...})[c]` as a reversed link (MD011). Use a named variable instead:
  ```js
  // BAD — triggers MD011 false positive
  function esc(s) { return String(s).replace(/[&<>"']/g, c => ({"&":"&amp;"})[c]); }

  // GOOD
  const ESC_MAP = {"&":"&amp;","<":"&lt;"};
  function esc(s) { return String(s).replace(/[&<>"']/g, c => ESC_MAP[c]); }
  ```

### 2. Link Check (`github-action-markdown-link-check`)

- Config: `.mlc-config.json`
- All URLs in markdown files must be reachable.
- **Do not** add placeholder or example URLs.

### 3. Verify Weapon Data (Python scripts)

These four scripts must pass **before** you commit any changes to `assets/data/*.json`:

```bash
cd tools
python extract_weapons.py --check        # checks assets/data/weapons.json
python extract_attack_ranges.py --check  # checks assets/data/attack_ranges.json
python extract_animations.py --check     # checks assets/data/animations.json
python extract_combos.py --check         # checks assets/data/combos_en.json and combos_kr.json
```

Run these from the `tools/` directory (they use relative imports).

**Critical rules for JSON files:**
- Never manually edit `assets/data/*.json` files. They are generated by the Python scripts.
- If you need to update JSON data, update the markdown/CSV source files and then re-run the corresponding extract script.
- The `--check` flag compares the on-disk JSON against what the script would generate. If they differ, CI fails.
- Key order, whitespace, and encoding (`ensure_ascii=False`) must match exactly.

**ETL pipeline (`tools/db_etl_pipeline.py`):**
- This script is verified to run in CI: `python tools/db_etl_pipeline.py`
- It creates `assets/data/elden_ring.db` (gitignored — do not commit it).
- The `--export` flag rewrites `assets/data/*.json` from the DB. **Do not use `--export` in CI** — it would overwrite the canonical JSON files and cause the `--check` scripts to fail on the next run if there is any format difference.
- If you add new tables or columns to the ETL pipeline, make sure the script still runs without errors.

### 4. Build Site (`mkdocs build --strict`)

```bash
pip install -r requirements.txt
mkdocs build --strict
```

The `--strict` flag turns warnings into errors. Common causes of failure:
- A page referenced in `mkdocs.yml` nav that does not exist.
- A markdown link to a page that does not exist within the docs.
- Invalid YAML in `mkdocs.yml`.

## Pre-Push Checklist

Before pushing any commit, verify:

- [ ] `cd tools && python extract_weapons.py --check` → exits 0
- [ ] `cd tools && python extract_attack_ranges.py --check` → exits 0
- [ ] `cd tools && python extract_animations.py --check` → exits 0
- [ ] `cd tools && python extract_combos.py --check` → exits 0
- [ ] `cd tools && python db_etl_pipeline.py` → exits 0
- [ ] `mkdocs build --strict` → exits 0

If any check fails, fix it before pushing. Do not push a broken state to `main` or any branch that CI watches.

---

## Branch Strategy

- Development branches: `claude/**`, `antigravity/**`, or `feat/**`
- Production branch: `main` (auto-deploys to GitHub Pages)
- CI runs on `main` and `claude/**` branches, and on all PRs targeting `main`.
- Never force-push to `main`.

---

## What NOT to Do

- Do not add new CI steps (`ci.yml`) without testing them locally first.
- Do not commit `assets/data/elden_ring.db` (it is gitignored for a reason).
- Do not regenerate JSON files using `--export` unless explicitly asked to do so.
- Do not add URLs to markdown files without verifying they are reachable.
- Do not modify `assets/data/*.json` directly; always go through the source files + extract scripts.
